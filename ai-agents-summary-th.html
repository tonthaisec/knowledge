AI Agents คืออะไร?

🔹 นิยามพื้นฐาน

AI Agent คือระบบอัตโนมัติ (autonomous system) ที่รวมความสามารถในการ ตัดสินใจ และ ลงมือทำ เข้ากับพลังของ Large Language Models (LLMs) โดยที่ LLM ทำหน้าที่เป็น "สมอง" ของ Agent ซึ่งรับผิดชอบการตีความภาษา สร้าง response และวางแผนการทำงาน ขณะที่ Agent framework เป็นตัวจัดการให้ LLM สามารถ execute task ได้จริงในโลกภายนอก

💡 ความแตกต่างสำคัญ:
LLM เฉยๆ = แค่สร้างข้อความ (text generation)
LLM + Agent Framework = สร้างข้อความ + ใช้เครื่องมือ + วางแผน + จดจำ + ดำเนินการ

🔹 จาก Static สู่ Agentic

Agentic design patterns ทำให้ AI models ก้าวข้าม static interactions ไปสู่ระบบที่สามารถ:

  • Dynamic Decision-Making — ตัดสินใจเลือกเส้นทางการทำงานแบบ real-time
  • Self-Assessment — ประเมินผลงานตัวเอง แล้วปรับปรุง
  • Iterative Improvement — ทำซ้ำรอบแล้วรอบเล่าจนได้ผลลัพธ์ที่ดีขึ้น
  • Tool Interaction — เรียกใช้เครื่องมือภายนอก เช่น API, database, web search
⚙️

ส่วนประกอบหลักของ AI Agent

🧠 LLM Backbone

เป็น "สมอง" หลักที่ทำหน้าที่ reasoning, สร้างภาษา และวางแผน ซึ่งจะถูก activate ผ่าน prompt template ที่ระบุว่า agent จะทำงานอย่างไรและมี tools อะไรบ้าง

👁️ Perception

รับ input จากสภาพแวดล้อม ไม่ว่าจะเป็นข้อความจาก user, ข้อมูลจาก API, หรือ observations จากเครื่องมือที่ใช้

💭 Reasoning

คิดวิเคราะห์ แยกแยะปัญหา ตัดสินใจว่าจะทำอะไรต่อ โดยใช้เทคนิคเช่น Chain-of-Thought (CoT) prompting

📋 Planning

วางแผนขั้นตอนการทำงาน แตก task ใหญ่เป็น subtasks ย่อย จัดลำดับ และปรับแผนเมื่อสถานการณ์เปลี่ยน

🧰 Tool Use

เรียกใช้เครื่องมือภายนอก เช่น web search, code interpreter, calculator, APIs ต่างๆ เพื่อทำงานที่ LLM ทำเองไม่ได้

💾 Memory

จดจำบริบท ทั้ง short-term (ภายใน session) และ long-term (ข้าม session) เพื่อให้การทำงานต่อเนื่องและเรียนรู้จากอดีต

🔗 Orchestration Layer: เป็นชั้นที่ประสานงานระหว่าง agents, tools, memory และ tasks โดยกำหนด control flow, sequencing และ error handling ซึ่งในระบบสมัยใหม่ จะแยก orchestration เป็น controller layer ออกมา ขณะที่ LLM โฟกัสแค่ local reasoning และ tool parameterization

4 Agentic Design Patterns หลัก

Andrew Ng ได้นำเสนอ 4 design patterns สำคัญสำหรับ AI agentic workflows ที่เป็นแกนกลางของระบบ AI Agent สมัยใหม่

Pattern 1 Reflection

Agent ประเมินผลงานตัวเอง ค้นหาจุดที่ต้องปรับปรุง แล้วสร้าง output ใหม่ที่ดีขึ้น เป็นการ "self-evaluate and iteratively refine"

ตัวอย่าง: ให้ LLM เขียนโค้ด → รันโค้ดดูว่ามี error ไหม → ถ้ามี error ก็ส่ง error message กลับไปให้ LLM แก้ → ทำซ้ำจนโค้ดผ่าน

Pattern 2 Tool Use

Agent ตัดสินใจเลือกเรียกใช้ function/tool ที่เหมาะสม เช่น web search, calendar, email, code execution เพื่อรวบรวมข้อมูลหรือดำเนินการ

ตัวอย่าง: ถามเรื่องสภาพอากาศ → Agent เรียก Weather API → ได้ข้อมูล → สร้างคำตอบจากข้อมูลจริง

Pattern 3 Planning

Agent วางแผนขั้นตอนทั้งหมดก่อนลงมือทำ โดยแตก complex task เป็น step-by-step plan ที่ execute ได้จริง และปรับแผนได้เมื่อเจอปัญหา

สำคัญ: Planning ไม่จำเป็นสำหรับทุก workflow — task ง่ายๆ ที่มีลำดับชัดเจน อาจใช้แค่ deterministic step-by-step approach ก็พอ

Pattern 4 Multi-Agent Collaboration

หลาย agents ทำงานร่วมกัน โดยแต่ละตัวมี role และความเชี่ยวชาญต่างกัน ช่วยกันแก้ปัญหาที่ซับซ้อนโดยแบ่งเป็น subtasks

ตัวอย่าง: สร้างซอฟต์แวร์ → แยกเป็น Agent: Software Engineer, Product Manager, Designer, QA Engineer แต่ละตัวทำหน้าที่ของตัวเอง

ReAct Framework: Reasoning + Acting

🔹 แนวคิดหลัก

ReAct (ย่อจาก Reasoning + Acting) เป็น framework ที่ให้ LLM สร้างทั้ง reasoning traces (ความคิด) และ task-specific actions (การกระทำ) สลับกันไป ถูกนำเสนอครั้งแรกในปี 2023 จาก paper "ReAct: Synergizing Reasoning and Acting in Language Models"

🔑 หลักการสำคัญ:
• Reasoning traces → ช่วยให้ model สร้าง, ติดตาม และปรับ action plan รวมถึงจัดการ exceptions
• Actions → ช่วยให้ model โต้ตอบกับแหล่งข้อมูลภายนอก เช่น knowledge base, APIs, environments

🔹 วงจร Thought → Action → Observation

ReAct agent ทำงานเป็น loop ซ้ำไปเรื่อยๆ จนกว่า task จะเสร็จ:

💭 Thought
คิดวิเคราะห์
→
⚡ Action
เรียก tool/API
→
👁️ Observation
ดูผลลัพธ์
→
🔄 Repeat
หรือ ✅ Answer

🔹 ตัวอย่าง ReAct Loop

// ตัวอย่าง: ถาม "ใครเป็นผู้ก่อตั้ง OpenAI?" Thought: ฉันต้องค้นหาข้อมูลเกี่ยวกับผู้ก่อตั้ง OpenAI Action: search("OpenAI founders") Observation: OpenAI ก่อตั้งโดย Sam Altman, Elon Musk, Greg Brockman... Thought: ได้คำตอบแล้ว สามารถตอบ user ได้ Action: finish("ผู้ก่อตั้ง OpenAI ได้แก่ Sam Altman, Elon Musk...")

🔹 ข้อดีของ ReAct

  • Adaptive: ปรับกลยุทธ์ได้ตาม observation — ถ้า tool fail ก็ลองวิธีอื่น
  • Interpretable: Thought steps ทำให้เห็น reasoning process ชัดเจน ช่วย debug ง่าย
  • Grounded: ลด hallucination เพราะดึงข้อมูลจริงจากภายนอกมาประกอบ
  • Flexible: ใช้ได้ตั้งแต่ simple RAG ไปจนถึง multi-agent workflows ที่ซับซ้อน

🔹 เปรียบเทียบ ReAct vs Plan-and-Execute

คุณลักษณะ ReAct Plan-and-Execute
แนวทาง คิดและทำสลับกันทีละ step วางแผนทั้งหมดก่อน แล้วค่อย execute ทีละ step
ความยืดหยุ่น สูง — ปรับเปลี่ยนแผนได้ทุก step ปานกลาง — ปรับแผนได้แต่ต้อง re-plan
LLM Calls มากกว่า (เรียกทุก step) น้อยกว่า (reasoning หลักอยู่ตอน plan)
เหมาะกับ Task ที่ไม่แน่นอน ต้องปรับตัว Task ที่ซับซ้อนแต่วางแผนได้ชัดเจน

Memory System ใน AI Agent

Memory คือระบบจัดเก็บข้อมูลที่ช่วยให้ Agent จดจำบริบท เรียนรู้จากอดีต และตอบสนองได้อย่างต่อเนื่อง แบ่งเป็นหลายระดับตามแนวคิดจากจิตวิทยาการรู้คิด (cognitive science)

⚡ Short-Term Memory

เก็บ context ภายใน session เดียว เช่น conversation turns ล่าสุด, intermediate reasoning results, session context

  • ใช้ conversation buffer หรือ in-memory cache
  • มี expiration timestamp
  • จำกัดโดย context window ของ LLM

🏛️ Long-Term Memory

เก็บข้อมูลข้าม session ดึงมาใช้เมื่อจำเป็น แบ่งย่อยเป็น 3 ประเภท:

📸 Episodic Memory

จดจำ "เหตุการณ์" ที่เกิดขึ้นในอดีตพร้อม temporal details เช่น "เมื่อ session ที่แล้ว user ให้อัพเดต Artifact X และชอบวิธี Y"

📚 Semantic Memory

เก็บ "ความรู้ทั่วไป" — facts, definitions, rules, preferences เช่น "User ชอบ dark mode, ทำงานสาย fintech"

🔧 Procedural Memory

เก็บ "วิธีการทำงาน" — workflows, skills, learned behaviors เช่น "ขั้นตอนอนุมัติ invoice: validate → route → notify"

🔹 Memory vs RAG

คุณลักษณะ RAG Agent Memory
หน้าที่ ดึงเอกสารภายนอกมาเสริม context เก็บ state, preferences, decisions ที่เปลี่ยนแปลงได้
ข้อมูล Static documents Evolving state — เรียนรู้จาก interactions
Personalization จำกัด สูง — จดจำ user preferences
วิวัฒนาการ RAG → Agentic RAG → Agent Memory ผสมผสานทุกระดับ

Tool Use — การใช้เครื่องมือภายนอก

🔹 ทำไมต้องใช้ Tools?

LLM เก่งเรื่อง reasoning แต่มีข้อจำกัดในเรื่อง: ข้อมูลไม่ real-time, คำนวณเลขไม่แม่น, เข้าถึงระบบภายนอกไม่ได้ ดังนั้น Tool Use จึงเป็น pattern ที่ให้ LLM ตัดสินใจเรียกใช้ function/API ที่เหมาะสมเพื่อแก้ปัญหาเหล่านี้

🔹 วิวัฒนาการของ Tool Use

2022 MRKL

Framework แรกๆ ที่รวม LLM กับ expert modules (ทั้ง LLM อื่นๆ หรือ symbolic tools เช่น calculator, weather API)

2023 Toolformer

Fine-tune LLM ให้เรียนรู้วิธีเรียก APIs เอง จาก dataset ที่สร้างขึ้นมา ทำให้ LLM รู้จัก tool name และ input parameters

2024-26 Function Calling + MCP

Function calling กลายเป็นมาตรฐาน + MCP (Model Context Protocol) จาก Anthropic กลายเป็น "USB-C ของ agent tool integration"

Planning — การวางแผนของ Agent

🔹 ทำไมต้อง Plan?

สำหรับ complex task ที่มีหลายขั้นตอน การวางแผนล่วงหน้าช่วยให้ Agent ทำงานได้มีประสิทธิภาพกว่า โดยแตก task ใหญ่เป็น executable steps ที่ชัดเจน แล้วปรับแผนเมื่อสิ่งที่คาดไว้ไม่เป็นไปตามนั้น

🔹 วิธีการ Planning ที่สำคัญ

📐 Task Decomposition

แตก task ใหญ่เป็น subtasks ย่อยๆ ที่ manage ง่ายกว่า เช่น "เขียนบทความ" → outline → research → draft → edit → review

🔄 Adaptive Re-planning

ปรับแผนได้เมื่อเจอ unexpected results — ไม่ใช่แค่ทำตาม plan เดิมอย่างเดียว

🌳 Tree of Thoughts

สำรวจหลาย reasoning paths พร้อมกัน เลือก path ที่ดีที่สุด เหมือนเล่นหมากรุกที่คิดหลาย moves ล่วงหน้า

📊 Plan-and-Execute

วางแผนทั้งหมดก่อนในขั้นตอนเดียว แล้วค่อย execute ทีละ step — ใช้ LLM calls น้อยกว่า ReAct

🔹 ตัวอย่าง Planning Flow

  1. รับ Task: "วิเคราะห์แนวโน้มตลาด AI ในไทย แล้วเขียนรายงาน"
  2. Decompose: แตกเป็น subtasks — ค้นหาข้อมูล, วิเคราะห์ trends, ระบุ key players, สรุปผล
  3. Select Tools: เลือก tools — web search, data analysis, document writer
  4. Execute: ทำทีละ step, เก็บ intermediate results
  5. Adapt: ถ้าพบข้อมูลใหม่ที่สำคัญ → ปรับแผนเพิ่ม subtask
  6. Synthesize: รวมผลทั้งหมดเป็นรายงานฉบับสมบูรณ์
👥

Multi-Agent Collaboration

🔹 แนวคิด

แทนที่จะใช้ Agent ตัวเดียวทำทุกอย่าง ให้แบ่งงานให้ หลาย Agents โดยแต่ละตัวมี role, expertise และ tools เฉพาะทาง ทำงานร่วมกันเหมือนทีมงานจริงๆ

🔹 ตัวอย่าง: สร้างซอฟต์แวร์ด้วย Multi-Agent

👔 Product Manager Agent

กำหนด requirements, จัดลำดับ features, ตัดสินใจ scope

💻 Software Engineer Agent

เขียน code, implement features, แก้ bugs

🎨 Designer Agent

ออกแบบ UI/UX, สร้าง mockups, กำหนด design system

🧪 QA Engineer Agent

เขียน test cases, ทำ testing, รายงาน bugs

🔹 รูปแบบการสื่อสารระหว่าง Agents

รูปแบบ คำอธิบาย ใช้เมื่อไหร่
Conversation-based Agents คุยกันผ่าน messages เหมือนแชท Tasks ที่ต้อง negotiate หรือถกเถียง
Task Delegation Agent หนึ่งมอบหมายงานให้อีกตัว Tasks ที่แบ่งหน้าที่ชัดเจน
Shared State Agents แชร์ state/memory ร่วมกัน Tasks ที่ต้องเห็นข้อมูลตัวเดียวกัน
Pipeline ส่งผลลัพธ์ต่อกันเป็นทอดๆ Tasks ที่มีลำดับขั้นตอนชัด

Agent Frameworks ยอดนิยม

ปัจจุบัน (2025-2026) มี frameworks หลักๆ ที่นิยมใช้สร้าง AI Agent systems ดังนี้:

🦜 LangChain / LangGraph

Modular Orchestrator — framework ที่เป็นที่นิยมที่สุด ทำให้การสร้าง chains, agents, memory integrations เป็นเรื่องง่าย

  • LangGraph ขยายเป็น multi-agent workflows ที่แต่ละ node เป็น agent ที่มี prompt, tools, logic ของตัวเอง
  • Production-ready ใช้งานจริงได้
Graph-based Modular Production

🤖 AutoGen (Microsoft)

Conversation-first Framework — ออกแบบมาเพื่อ multi-agent collaboration ผ่าน conversation

  • Agents แลกเปลี่ยน messages, delegate tasks, หา consensus ผ่าน structured dialogue
  • เหมาะกับ scenarios ที่ต้องถกเถียง/ปรึกษากัน
Conversation Multi-Agent Production

🚢 CrewAI

Role-based Task Execution — สร้าง "ทีม" ของ agents ที่มี role ชัดเจน

  • สถาปัตยกรรม 2 ชั้น: Crews (dynamic, role-based collaboration) + Flows (deterministic, event-driven orchestration)
  • เหมาะกับงานที่แบ่งบทบาทชัดเจน
Role-based Crew/Flow Production

🔗 OpenAI Agents SDK + Others

Vendor SDKs — SDK จาก AI labs ใหญ่ๆ ที่ให้ native agent capabilities

  • OpenAI Agents SDK, Claude Agent SDK (Anthropic)
  • ใหม่กว่าแต่ backed โดย major AI labs
Native First-party Evolving
🔌 MCP (Model Context Protocol): มาตรฐานเปิดจาก Anthropic สำหรับเชื่อมต่อ agents กับ tools — กำลังกลายเป็น "USB-C ของ agent tool integration" ทุก framework กำลัง adopt MCP เป็นมาตรฐานกลาง

🔹 สรุป Key Takeaways สำหรับ AI Engineer

1. เข้าใจ Core Loop: Agent = LLM + Tools + Memory + Planning ทำงานเป็น loop ของ Perceive → Think → Act → Observe
2. เลือก Pattern ให้เหมาะ: ไม่จำเป็นต้องใช้ทุก pattern — task ง่ายๆ อาจแค่ tool use ก็พอ, task ซับซ้อนค่อยเพิ่ม planning + multi-agent
3. Memory เป็นตัวแบ่ง: Agent ที่มี memory ดี = personalized + context-aware ส่วน agent ที่ไม่มี memory = stateless ทุก interaction
4. Production != Research: ใน production ต้องคิดเรื่อง error handling, cost management, latency, observability ด้วย ไม่ใช่แค่ accuracy
